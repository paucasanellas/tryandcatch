# i18n

Cómo funciona la internacionalización: **`@nuxtjs/i18n` con el castellano como idioma base**.

## Configuración

- `defaultLocale: 'es'` con `strategy: 'prefix_except_default'`: el castellano vive sin prefijo (`/`, `/articulos`); los futuros idiomas, con él (`/en/…`).
- `detectBrowserLanguage: false`: el idioma lo decide la URL, no el navegador.
- El `lang` del `<html>` lo pone `useLocaleHead()` desde `app.vue` — el módulo no lo hace solo.

## Traducciones

- Un fichero por locale en `app/locales/<code>.json`.
- **Las claves van planas a primer nivel**, con puntos en el nombre — nunca objetos anidados.

```json
{
  "app.name": "Try and Catch",
  "nav.articles": "Artículos"
}
```

- En componentes: `$t('app.name')` en plantillas, `useI18n()` en script.
- **Ningún texto visible se escribe en el componente**: todo pasa por una clave.

## Rutas localizadas

- **Las carpetas, páginas, componentes y nombres de ruta se mantienen en inglés.** Cada página declara sus rutas localizadas con `definePageMeta`.
- `app/pages/articles/index.vue` conserva el nombre de ruta `articles` y se publica como `/articulos` en castellano.
- `app/pages/articles/[slug].vue` conserva el nombre `articles-slug` y se publica como `/articulos/[slug]`.
- `customRoutes: 'meta'` vive en `nuxt.config.ts`. Las traducciones concretas viven junto a su página en `definePageMeta({ i18n: { paths } })`.
- Navegación y CTAs llaman a `useLocalePath()` con el nombre de ruta. No construyen ni traducen URLs a mano.

## Añadir un idioma

1. Crear `app/locales/<code>.json` con todas las claves traducidas.
2. Añadir su entrada en `locales` de `nuxt.config.ts` (`code`, `language`, `name`, `file`).
